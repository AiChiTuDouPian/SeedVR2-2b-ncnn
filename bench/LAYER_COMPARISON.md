# 逐层（逐块）数值对拍报告

> 平台：NVIDIA GeForce RTX 5060 Ti 16GB ｜ ncnn Vulkan ｜ Windows / MinGW-w64
> 输入：椎名真白 1131×960（`input/椎名真白.png`）｜ seed 42
> 日期：2026-09-10 ｜ 数据来源：`diag/layer_cmp/`（不入库，见 §4 复现）

本报告回答一个问题：**低精度（bf16 / fp16）的 32 层 NaDiT，误差是逐层怎么累积的？**
以 **fp32 残差链** 为基准，按**层号**对齐后逐层对拍 vid 流（形状 `(Lv, 2560)`，fp32）。

---

## 1. 结论速览

| 分辨率 | 精度 | 第 2 层 cos | 第 30 层 cos（最小） | 判定 |
|---|---|---:|---:|---|
| 360p | **bf16** | 0.99999130 | **0.99951745** | ✅ 几乎无损，单调缓慢衰减 |
| 360p | fp16 | 0.99999987 | **0.90010460** | ❌ 第 12 层跌破 0.996，不可用 |
| 720p | **bf16** | 0.99999144 | **0.99933130** | ✅ 几乎无损 |
| 720p | fp16 | 0.99999986 | **0.93186509** | ❌ 同上 |

三条要点：

1. **bf16 在 30 层内几乎无损**：cos 从 0.9999913 缓慢降到 0.9993~0.9995，`mean|d|` 仅 0.02~0.023。
   32 层累积下来仍是 3~4 个 9，是低精度的安全选择。
2. **fp16 是「先好后崩」**：前 4 层比 bf16 还准（cos 0.9999999，因 fp16 尾数 10 位 > bf16 的 7 位），
   但从第 6 层开始被 **指数范围窄**（fp16 最大 65504、最小正规数 6e-5）拖累，第 12 层跌破 0.996，
   到第 30 层只剩 **0.90 / 0.93**。
3. **fp16 的误差不是「精度不够」而是「动态范围不够」**：`max|d|` 到第 30 层已达 20~23，
   而 bf16 同期只有 3.8~13。即 fp16 在少数通道上出现了大偏差（接近溢出/下溢的通道），
   而 bf16 的偏差是全局均匀的小噪声。
   → **生产应选 bf16**（与 `bench/PT_COMPARISON.md` 的图像级结论一致）。

## 4. 对比文件清单（怎么复现）

### 4.1 工具

| 文件 | 作用 |
|---|---|
| `tools/layer_cmp.py` | **逐层对拍脚本**。读 dump 目录，按层号对齐，输出 cos / max\|d\| / mean\|d\| 表 |
| `src/dit_graph.cpp`（`SEEDVR_DUMP_BLOCKOUT=1`） | 引擎侧 dump 开关：每块末把 `vid_cur` 写成 `blkout_{b}_vid.f32`（裸 fp32，`(Lv,2560)`） |

`layer_cmp.py` 按**层号**（= `(块号+1)×chunk`）对齐，因此 **chunk=1 与 chunk=2 的 dump 可以混用**
（本报告里 fp32/bf16 用 chunk=2、fp16 用 chunk=1，正是靠这个机制对齐的）。

### 4.2 数据（`diag/layer_cmp/`，不入库）

```
diag/layer_cmp/
  360_fp32/   blkout_0..14_vid.f32 + out_360_fp32.png + run_360_fp32.log   (chunk=2)
  360_bf16/   blkout_0..14_vid.f32 + out_360_bf16.png + run_360_bf16.log   (chunk=2)
  360_fp16/   blkout_0..30_vid.f32 + out_360_fp16.png + run_360_fp16.log   (chunk=1)
  720_fp32/   720_bf16/   720_fp16/                                       同上
```

每个 `blkout_{b}_vid.f32` = `Lv × 2560 × 4` 字节裸 fp32（360p 为 1589760 元素，720p 为 6105600 元素）。

### 4.3 复现命令

⚠️ dump 文件名是**相对路径**（`blkout_%d_vid.f32`，`src/dit_graph.cpp:504`），写到**当前工作目录**，
所以每档精度要在各自的空目录里跑，产物自然分开：

```bash
EXE=$PWD/build-cmake/seedvr2_run.exe
SRC=$PWD/input/椎名真白.png

# 1) 三档精度各跑一次，各自 dump 到独立目录
#    fp32 / bf16 走 chunk=2（块 b = 层 [2b,2b+2)）→ blkout_0..14 = 层 2/4/…/30
#    fp16        走 chunk=1（块 b = 层 b+1）    → blkout_0..30 = 层 1/2/…/31
mkdir -p diag/layer_cmp/360_fp32 && (cd diag/layer_cmp/360_fp32 && \
    SEEDVR_DUMP_BLOCKOUT=1 $EXE $SRC out_360_fp32.png --resolution 360  > run_360_fp32.log 2>&1)
mkdir -p diag/layer_cmp/360_bf16 && (cd diag/layer_cmp/360_bf16 && \
    SEEDVR_DUMP_BLOCKOUT=1 $EXE $SRC out_360_bf16.png --resolution 360 --bf16 > run_360_bf16.log 2>&1)
mkdir -p diag/layer_cmp/360_fp16 && (cd diag/layer_cmp/360_fp16 && \
    SEEDVR_DUMP_BLOCKOUT=1 $EXE $SRC out_360_fp16.png --resolution 360 --fp16 > run_360_fp16.log 2>&1)

# 2) 逐层对拍（fp32 为基准；注意 fp16 跑的是 chunk=1，靠层号对齐）
python tools/layer_cmp.py --ref fp32=diag/layer_cmp/360_fp32:2 \
                          --cmp bf16=diag/layer_cmp/360_bf16:2 \
                          --cmp fp16=diag/layer_cmp/360_fp16:1
```

> 若低精度块图缺 `c2` 变体，引擎会打印 `[engine] chunk=2 块图不可用，回退 chunk=1`
> 并退回 32 块（dump 变为 `blkout_0..30`，此时 `layer_cmp.py` 的 chunk 参数要传 1）。
> 块图导出见 `README.md`「生成合并计算图块」。

## 5. 对设计的影响

1. **bf16 是低精度的正确默认**：30 层 cos ≥ 0.9993，图像级 PSNR 45~46 dB（见 `PT_COMPARISON.md`）。
2. **fp16 仅在「层数很少」时有优势**：前 4 层它比 bf16 准，若未来做浅层模型/单层验证，
   fp16 反而更好；但 32 层深度下必须排除。
3. **残差链保持 fp32 是必要的**（`dit_graph.cpp` 中 `mres_i_v` 把 mlp 输出 cast 回 f32 再 ADD）：
   若残差也走低精度，上述误差会进一步加速累积。
