# SeedVR2-ncnn vs PyTorch 精度对比报告

> 日期：2026-09-10 ｜ 平台：RTX 5060 Ti 16GB ｜ ncnn Vulkan vs 官方 PyTorch（ComfyUI-SeedVR2 VideoUpscaler）
> 输入：**椎名真白** `input/椎名真白.png`（1131×960，非官方示例图）｜ seed 42
> 数据来源：`bench/run_pt_compare.sh` → `diag/pt_compare_20260910/summary.log`

## 1. 对拍口径（决定结果是否可信，务必先读）

与官方 PyTorch 对拍有 **3 个必须对齐的条件**，任一条不满足，PSNR 就失去意义：

| # | 条件 | ncnn 侧 | 官方侧 | 不对齐的后果 |
|---|---|---|---|---|
| 1 | **色彩校正必须两边同关** | `--no-colorfix` | `--color_correction none` | 两边算法实现不同（ncnn = LAB transfer 强度 0.8；官方 = 小波多尺度）。只关一边会引入全局色调差：1080p PSNR 从 **46.55 dB 掉到 27.36 dB** |
| 2 | **seed 必须一致** | `--seed 42`（默认值） | `--seed 42` | 初始噪声不同 → 输出完全不同。引擎用 `rng::PhiloxRandn` 复刻 CUDA Philox4x32-10，与 `torch.randn(CUDA)` 同源，故噪声可逐位对齐 |
| 3 | **DiT 权重来源要认** | 由官方权重导出的 ncnn fp16 权重 | `seedvr2_ema_3b_fp16.safetensors` | 官方 fp8 权重与 ncnn 权重不同源，会带来约 9% 的固有底噪。**图像级 ground truth 必须用官方 fp16 全流程图** |

色彩校正一条已做**闭环验证**：

```
同一 PT 参考 mashiro_pt1080.png（md5 5d4e1155…）
  vs ncnn fp32 --no-colorfix : cos 0.999977 / PSNR 46.55 dB
  vs ncnn fp32 默认(开校正)  : cos 0.998534 / PSNR 27.36 dB
两个 ncnn 产物之间            : cos 0.998711 / PSNR 28.01 dB   ← 差值自洽
```

参考图由 `tools/pt_reference.py` 生成，已验证可**逐位复现**历史参考
（新生成的 `pt_ref/mashiro_pt1080.png` 与 `diag/mashiro_pt_latent.png` md5 相同）。

## 3. 精度内自比：低精度 vs fp32（纯量化误差，不含跨实现差异）

以同分辨率的 **ncnn fp32** 为基准，隔离出低精度本身引入的误差：

| 分辨率 | bf16 vs fp32 | | | fp16 vs fp32 | | |
|---|---:|---:|---:|---:|---:|---:|
| | cos | **PSNR** | max\|d\| | cos | **PSNR** | max\|d\| |
| 360p | 0.999931 | **41.68 dB** | 0.1569 | 0.995799 | 23.67 dB | 0.9176 |
| 720p | 0.999977 | **47.30 dB** | 0.1020 | 0.998693 | 29.09 dB | 0.7490 |
| 1080p | 0.999981 | **48.16 dB** | 0.0980 | 0.999203 | 30.53 dB | 0.5686 |

**结论：bf16 ≈ 无损（41.7~48.2 dB），fp16 有明显失真（23.7~30.5 dB）。生产低精度请用 `--bf16`。**

### 3.1 后端交叉验证：CPU vs GPU（360p fp32）

CPU 路径（`--cpu`，关闭 Vulkan compute，走 C++ 注意力参考 + ncnn CPU GEMM）
与 GPU 路径在 360p fp32 下几乎逐位一致：

| 对比 | cos | PSNR | mean\|d\| | max\|d\| |
|---|---:|---:|---:|---:|
| CPU fp32 vs GPU fp32 | **1.000000** | **80.52 dB** | 0.00000 | 0.0039 |
| CPU fp32 vs PyTorch | 0.995548 | 23.08 dB | 0.04682 | 0.9137 |
| GPU fp32 vs PyTorch | 0.995548 | 23.08 dB | 0.04682 | 0.9137 |

CPU 与 GPU 的指标**完全相同**（同一 cos / PSNR / SSIM）→ 两条后端的差异远小于它们与
PyTorch 的差异，说明该档位的差距来自 PyTorch 侧的任务敏感性（见 §4），而非 ncnn 后端实现。

> CPU 路径 1080p 因系统内存不足无法运行，详见 [`PERFORMANCE_ANALYSIS.md`](PERFORMANCE_ANALYSIS.md) §4。

机理（详见 `docs/GPU加速与自定义算子技术文档.md` §3.4 / §5.2）：

- ncnn 中**没有任何 Vulkan 层声明 `support_bf16_storage`**（`layer.cpp` 默认 false）
  → bf16 激活在层间自动 cast 回 fp32，**bf16 只作用于 GEMM 内核**（tensor core + fp32 累加）；
- fp16 则是**整链真实 fp16 存储**（含层间激活），32 层逐层量化误差累积
  （block0 cos≈1.0 → block30 cos≈0.88）；
- 两者速度相同（都被块间搬运支配），因此 fp16 无任何实用增益。

## 4. 为什么 PSNR 随分辨率单调变化？—— 缩放比对照实验

主矩阵呈现明显的分辨率依赖（23.1 / 34.8 / 46.6 dB）。假设是**任务缩放比**所致：
SeedVR2 是超分/复原模型，当输入被**缩小**时网络进入训练分布之外的区间，
雅可比更大，两个实现之间任何微小数值差异都会被放大。

**对照实验**：把源图预缩到 212×180 再跑 `--resolution 360`，
使有效缩放比从 0.375× 变成 **2.0×（真放大，回到训练分布）**：

| 360p 任务 | 有效缩放 | 精度 | cos | **PSNR** | SSIM |
|---|---|---:|---:|---:|---:|
| 源 1131×960 | 0.375×（缩小，**分布外**） | fp32 | 0.995548 | **23.08 dB** | 0.9070 |
| **源 212×180** | **2.0×（真放大，分布内）** | **fp32** | **0.999963** | **45.82 dB** | **0.9981** |
| 源 212×180 | 2.0× | bf16 | 0.999931 | 43.11 dB | 0.9971 |
| 源 212×180 | 2.0× | fp16 | 0.997386 | 26.61 dB | 0.9305 |

**同一分辨率、同一代码，仅改变任务缩放比，PSNR 从 23.08 dB 跃升到 45.82 dB（+22.7 dB）。**

把 4 组数据放在一起，规律非常干净：

| 任务 | 有效缩放 | fp32 vs PyTorch |
|---|---:|---:|
| 360p（源 1131×960） | 0.375× | 23.08 dB |
| 720p（源 1131×960） | 0.75× | 34.81 dB |
| 1080p（源 1131×960） | 1.125× | 46.55 dB |
| 360p（源 212×180） | 2.0× | 45.82 dB |

⇒ **PSNR 只由「任务缩放比」决定，与输出分辨率本身无关。**
凡缩放比 ≥1×（模型分布内的真超分任务），ncnn 与 PyTorch 的一致性稳定在 **45~46.6 dB**
（cos ≥ 0.99996、SSIM ≥ 0.998），即**实现层面已数值等价**。

> 因此主矩阵中 360p / 720p 的低 PSNR **不是实现缺陷**，而是超分模型在缩小任务下的固有敏感性。
> 若要把这两个档位当作质量验收口径，应改用「先缩小源图、再做真放大」的任务设定。

## 5. 结论

1. **1080p fp32：46.55 dB / cos 0.999977 / SSIM 0.9978**，且与 2026-09-10 01:52 的历史产物
   **逐位一致** → 引擎完全可复现，实现与官方 PyTorch 数值等价。
2. **1080p bf16：45.45 dB / cos 0.999962**，相对 fp32 仅损失约 1 dB，且比 fp32 快 **1.72×**
   （114 s vs 196 s）→ **生产推荐 `--bf16`**。
3. **fp16 不推荐**：31.06 dB（vs PyTorch）/ 30.53 dB（vs fp32），速度与 bf16 相同但精度差一个量级。
4. 低 PSNR 档位（360p/720p）已由缩放比对照实验解释：**任务缩放比 ≥1× 时一致性 45~46.6 dB**。
5. 已闭环排除的干扰项：
   - 色彩校正口径差异（46.55 → 27.36 dB，差 19 dB）；
   - 参考图不可复现（`tools/pt_reference.py` 生成的参考与历史参考 md5 相同）；
   - 官方 PyTorch 自身的运行间非确定性（两次独立 360p 运行之间为 44.69 dB，远高于 23 dB 的差距）；
   - 窗口几何实现差异（引擎 `awa_window.cpp` 是官方 `make_720Pwindows_bysize` 的逐行等价移植，
     360p 实测 `ns.nwin=4` 与公式 `nh=ceil(23/14)=2, nw=ceil(27/22)=2` 吻合）。

## 6. 复现

```bash
# 1) 生成官方 PyTorch 参考（口径已固定在脚本内）
python tools/pt_reference.py input/椎名真白.png F:/Seedvr2/pt_ref/mashiro_pt1080.png 1080

# 2) ncnn 侧（--no-colorfix 是必须的）
./build-cmake/seedvr2_run.exe input/椎名真白.png out_fp32.png --resolution 1080 --no-colorfix
./build-cmake/seedvr2_run.exe input/椎名真白.png out_bf16.png --resolution 1080 --no-colorfix --bf16
./build-cmake/seedvr2_run.exe input/椎名真白.png out_fp16.png --resolution 1080 --no-colorfix --fp16

# 3) 一键跑完整矩阵 + 自动对拍
bash bench/run_pt_compare.sh

# 4) 缩放比对照实验
bash bench/run_scale_control.sh
```

`tools/img_metrics.py` 的口径：PSNR = `10*log10(1/MSE)`（[0,1] 浮点域，等价于 8bit 域的
`10*log10(255²/MSE)`）；SSIM 为 8×8 灰度滑窗。
